# ConRAD: Conformal Risk-Aware Neural Databases

ConRAD is a framework that enforces **declarative recall guarantees** in neural graph database query engines. Given a user-specified risk budget, it derives per-operator prediction thresholds via **Conformal Risk Control** (finite-sample, distribution-free validity) while maximizing end-to-end precision. 

## Requirements

- **Python**: 3.10
- **Neo4j**: Used as the graph backend (see `build.sh` and `scripts/install_neo4j.sh`)
- **PyTorch** and **PyTorch Geometric**: See `requirements-cpu.txt` or `requirements-gpu.txt`

### Installation

```bash
# CPU
pip install -r requirements-cpu.txt

# GPU (CUDA 12.1)
pip install -r requirements-gpu.txt
```

The project setup (data dirs, Neo4j) is driven by `build.sh`.

## Repository layout

| Path | Description |
|------|-------------|
| `src/conformal_prediction/` | Conformal Risk Control: calibration, vector thresholds, quantile-space scalarization |
| `src/models/topology/` | Query pipelines: `ThreeHopPipeline`, `TwoUnionPipeline`, `TwoIntersectProjectPipeline` |
| `src/inference/` | Model loading and inference (ULTRA / UltraQuery) |
| `src/graph_handler/` | Neo4j backend and graph access |
| `src/sampler/` | Calibration and query sampling |
| `scripts/` | Dataset processing (`process_dataset.py`), calibration data generation (`generate_calibration.sh`), Neo4j helpers |
| `plots/` | Scripts and figures for validity, efficiency, baselines, abstention |

## Data and artifacts

- **Graph data**: `artifacts/data/<dataset>/` (e.g. `fb15k-237`, `nell-955`, `yago310`). Populated by `scripts/process_dataset.py`.
- **Calibration & test queries**: `artifacts/queries/<dataset>/calibration/<query_type>/` and `artifacts/queries/<dataset>/test/<query_type>/`. Generated by `scripts/generate_calibration.sh` (uses `build.sh` and Neo4j).
- **Model checkpoints**: `artifacts/snapshots/` (e.g. `ultraquery`, `ultra_nell955`). 

Query topologies: `3p_pipeline`, `2u_pipeline`, `2ip_pipeline` (aligned with the three pipeline classes above).

## Running ConRAD

All commands below assume you are in the **repository root** unless noted.

### 1. Prepare data and calibration

```bash
# Prepare dataset (if not already under artifacts/data/)
python scripts/process_dataset.py fb15k-237   # or nell-955, yago310

# Generate calibration (and test) queries for a given incompleteness level (e.g. 20% missing)
bash scripts/generate_calibration.sh --dataset fb15k-237 --delete-edges-perc 20
```

Neo4j must be running and configured as in `build.sh` / your config.

### 2. Run ConRAD benchmark (calibration + evaluation)

From `src/`:

```bash
cd src

# Single pipeline, one incompleteness level, default confidence levels
python -u run_crc_benchmark_auto.py \
  --dataset fb15k-237 \
  --incompleteness 20 \
  --model_to_infer ThreeHopPipeline \
  --use-ultraquery

# Optional: custom confidence levels and eval limit
python -u run_crc_benchmark_auto.py \
  --dataset fb15k-237 \
  --incompleteness 20 \
  --model_to_infer ThreeHopPipeline \
  --confidence-levels 0.7 0.8 0.9 \
  --max-eval-queries 1000 \
  --use-ultraquery
```

Results are written under `artifacts/benchmark/conrad_bench_<dataset>_<model>_<incompleteness>/` (e.g. `results_summary.csv`, logs, and optionally `calibrated_lambdas.json`).

Other pipelines:

- `TwoUnionPipeline` (2u)
- `TwoIntersectProjectPipeline` (2ip)

### 3. Full sweep (multiple datasets, incompleteness levels, models)

```bash
cd src
bash run.sh
```

Edit variables at the top of `run.sh` (e.g. `INCOMPLETENESS_LEVELS`, `DATASETS`, `MODELS`, `CONFIDENCE_LEVELS`) to control the sweep.

### 4. Low-level: calibration only or benchmark only

```bash
cd src
python -u validate_crc_composition.py \
  --dataset fb15k-237 \
  --model_to_infer ThreeHopPipeline \
  --confidence 0.8 \
  --mode both \
  --max-calibration-queries 100 \
  --max-eval-queries 1000 \
  --use-ultraquery
```

`--mode`: `calibration` | `benchmark` | `both`. Use `--lambdas-file <path>` to reuse previously calibrated lambdas (skip calibration).

## Baselines

From `src/`:

```bash
python -u run_baseline_benchmarks.py \
  --query-dir ../artifacts/queries/fb15k237/test/3p_pipeline \
  --dataset fb15k-237 \
  --baseline-type neural \
  --ultra-thresholds 0.7 0.8 0.9 \
  --use-ultraquery
```

`--baseline-type`: `symbolic` (Neo4j only), `neural` (static thresholds), `hybrid` (neural + symbolic with static thresholds). See script docstring and `--help` for options.

## Plots

Under `plots/`: scripts for validity, efficiency, abstention, and baseline comparisons (e.g. `plots/validity/validity.py`, `plots/efficiency/efficiency.py`, `plots/abstention/abstention.py`). They expect results under `artifacts/benchmark/` (and optionally other artifact dirs). Run with the same Python env as the main codebase.
